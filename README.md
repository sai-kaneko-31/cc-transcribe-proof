# transcribe

音声と動画を、あなた自身の AWS アカウントの Amazon Transcribe で日本語に書き起こし、書き起こしの誤認識だけを別の Claude が直す Claude Code のプラグインです。

AWS と Anthropic の公式のものではなく、個人が作っています。

## 何をするか

- 音声か動画のファイルを、Amazon Transcribe で書き起こす。話者ごとに分けて、`[00:12 spk_1] 本文` の形の行にする。
- 書き起こしの誤認識だけを直す。同音語の取り違え、重なった語や文、崩れた語、数字と単位の取り違えが対象。
- 言い換え、要約、敬語の調整、表記の揺れ、句読点は直さない。確信が持てない箇所は、直さずに「要確認」の一覧へ出す。
- 書き起こしの本文を直すのは、`Read` しか使えない別の Claude。本文を書き換えるのは、返ってきた編集を機械的に当てるスクリプトだけ。

対応する言語は日本語（ja-JP）だけです。動作を確かめた OS は macOS で、Linux でも動くように書いてありますが、実機では確かめていません。Windows は未対応です（動くかを確かめていません）。1 回に扱えるのは、長さ 120 分、大きさ 2 GB までです。

## 必要なもの

- Claude Code
- AWS アカウント（IAM ユーザーとバケットを作れる権限、またはそれを持つ管理者）
- AWS CLI v2、jq、ffprobe（ffmpeg に入っています）、bash

## 入れ方

Claude Code で、次の 2 つを実行します。

```text
/plugin marketplace add sai-kaneko-31/cc-transcribe
/plugin install transcribe@transcribe
```

## 準備

```text
/transcribe:setup
```

AWS 側の準備を案内します。作るものは、専用の S3 バケット 1 つと、権限を絞った IAM ユーザー 1 つです。`setup` は AWS に何も作らず、鍵も扱いません。IAM を作れない人のために、管理者へ渡す文書も出します。

アクセスキーとバケット名は、次の環境変数に設定します。名前をこのプラグイン専用にしているのは、`AWS_ACCESS_KEY_ID` などの標準の名前に、より広い権限の鍵が入っていることがあるためです。標準の名前を使うと、権限を絞った意味が黙って無くなります。

- `TRANSCRIBE_AWS_ACCESS_KEY_ID`
- `TRANSCRIBE_AWS_SECRET_ACCESS_KEY`
- `TRANSCRIBE_AWS_REGION`
- `TRANSCRIBE_S3_BUCKET`

このプラグインは、`.env`、`~/.aws`、`AWS_PROFILE` を読みません。環境変数は、Claude Code を起動するシェルに設定します。

設定したら、確認します。

```text
/transcribe:verify
```

音声を送らずに、環境変数の形、鍵の持ち主、鍵が IAM のユーザー一覧を読めないこと、バケットの権限、バケットが versioning を有効にしていないこと、Transcribe の 3 つの操作（開始・取得・削除）を調べます。鍵が他のバケットの読み取りなどを持っていないことまでは、確かめません。

## 使い方

```text
/transcribe:transcribe <音声か動画のファイル> [話題を 1 文] [話者は最大 N 人]
```

実行のたびに、次を確かめます。音声の送り先（あなたの AWS アカウントの S3 と Amazon Transcribe）、書き起こしの本文の送り先（修正のために Claude）、概算の料金、依頼主の音声のときは契約が許すかどうか。同意が出るまで、音声は送られません。

出力は、入力ファイルと同じディレクトリに作られます。既にあるファイルは上書きしません。

- `<名前>.transcript.json`: Amazon Transcribe の結果そのまま
- `<名前>.transcript.txt`: 話者ごとの行にした書き起こし
- `<名前>.corrected.txt`: 誤認識を直した書き起こし
- `<名前>.corrections.json`: 当てた編集、当てなかった編集、要確認の箇所

出力先が git の作業ツリーの中で、`.gitignore` に無視されていないときは、警告します。依頼主の声の内容を git に入れないためです。無視するには、`.gitignore` に `*.transcript.*`、`*.corrected.txt`、`*.corrections.json` を足します。

ほかのツールで作った書き起こしの、修正だけを使うこともできます。AWS には触れません。

```text
/transcribe:correct <書き起こしのテキストファイル> [話題を 1 文]
```

## 内容の行き先と料金

- 音声: あなたの AWS アカウントのバケットに一時的に置かれ、文字起こしのあとに削除される。バケットのライフサイクルも、1 日で消す。AWS は、サービスの改善のために内容を保存することがある。止めるには、AWS Organizations の AI サービスのオプトアウトポリシーを使う。
- 書き起こしの本文: 修正のために、Claude（Anthropic）が読む。Claude Code のセッションの記録として、手元の `~/.claude/projects/` にも残る。保持の日数は、設定の `cleanupPeriodDays` で変えられる。
- 料金: あなたの AWS アカウントに、Amazon Transcribe の料金がかかる。実行前に出す金額は概算で、単価は、料金のページの us-east-1 の例（1 分あたり 0.006 ドル）。リージョンによって違うことがある。Claude の利用料金も別にかかる。

## 安全のための作り

- AWS に触れるのは、ラッパースクリプト `transcribe.sh` だけ。AWS CLI を、スキルが直に打つことはない。
- スクリプトは、呼び出し元の環境を捨て、プラグイン専用の 4 つの変数から鍵を組む。ほかの AWS の鍵、プロファイル、エンドポイントの指定、設定ファイルは、AWS CLI に届かない。AWS CLI と jq は、空の HOME で動かす。`~/.aws/cli/alias` と `~/.jq` は読まれない。
- すべての S3 の呼び出しに、`--expected-bucket-owner` を付ける。バケット名の打ち間違いや乗っ取りで、他人のバケットへ音声が上がるのを防ぐため。
- 置くオブジェクトの名前とジョブ名は、乱数。依頼主の名前やファイル名を、AWS へ出さない。
- 結果は、`--output-bucket-name` と IAM の権限で取る。署名つきの URL は使わない。
- 処理が成功した場合も、失敗した場合も、シグナルで止まった場合も、置いた音声・結果・ジョブを AWS から消す。Transcribe が出力先に残す空の確認用ファイル（`.write_access_check_file.temp`）も消す。音声を先に消す。後片付けの途中で届いたシグナルは無視する。消せなかったものは名指しする。バケットが versioning を有効にしていると、消した物は古い版として残るので、そのことも警告する。
- 書き起こしの本文は、後片付けのあとに、修正役だけが読む。書き込みと実行の権限を持つ本体の会話は、本文を読まない。標準出力にはパスだけを出す。
- 音声を送る `run` は、スキルの事前承認に入れていない。通常の設定では、Claude Code の確認が出る。auto モードや利用者の許可設定によっては出ないことがあり、そのときは、スキルの手順にある確認の質問だけが、音声が手元を出る前の確認になる。
- 本文には、録音に入った「AI への指示」のような文が混ざりうる。修正役は本文をデータとして扱い、`Read` しか使えない。ただし、`Read` の範囲は Claude Code の許可設定に従い、指定したファイル以外を読めないようにはしていない。編集は、形が正しく、行の中にちょうど 1 回ある文字列だけに当たる。話者ラベルは変えない。`new` は `old` の 3 倍と 20 文字までで、1 つの行が元の長さの 1.5 倍と 20 文字を超えて伸びる編集は当たらない。制御文字と書式文字は入れられない。

## 確かめていないこと

- 実録音での精度。検証はすべて、macOS の `say` で作った合成音声。
- ap-northeast-1 以外のリージョンと、KMS で暗号化したバケット。
- 失敗したジョブの請求。`verify` は、音声ではないファイルで失敗するジョブを 1 つ作る。
- 修正役が、指定したファイル以外を読まないこと。本文の指示に従うかは、評価ケースで確かめる予定だが、まだ回していない。
- 話題を渡す効果。合成音声では、見えなかった。
- 話者の名前。`spk_0` のような番号のままで、誰かの特定はしない。
- カスタム語彙と、候補の複数表示は使っていない。合成音声の 2 本では、効果が見えなかった。

## 開発

```bash
bash tests/run.sh
shellcheck --severity=warning plugins/transcribe/scripts/*.sh tests/*.sh
claude plugin validate .
```

テストは、偽の `aws`、`ffprobe`、`sleep` を PATH の先頭に置いて回します。AWS のアカウントには触れません。`jq` が無い環境では、一部のテストが `SKIP` になり、その経路は確かめられていません。

誤認識の修正の評価は、`plugins/transcribe/evals/` にあります。回し方は、そこの README にあります。
